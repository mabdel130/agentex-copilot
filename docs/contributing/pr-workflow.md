# Contributing a Pull Request

1. Review the relevant skill, agent, shared-library, and policy documentation before editing.
2. Keep the change scoped and preserve consumer-project compatibility.
3. Add or update focused tests and evaluation cases when behavior changes.
4. Update user documentation for user-visible behavior or configuration changes.
5. Run the smallest applicable existing validation command.
6. In the pull request, explain the behavior change, validation performed, and any compatibility
   consideration.

Before requesting review, confirm no `.env` data, saved auth state, generated execution artifacts,
or proprietary fixture data is included.
